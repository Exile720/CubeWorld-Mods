# 背包分类的本地证据

依据为本机已核实的 2013 Alpha 客户端，以及项目固定版本的 Qube Loader 和 CubeWorld-Reversal。恢复源码名称可能有误，以实际指令交叉核对，不把它当作完整原版源码。

- 游戏 SHA256：`84A7A132A84D4282338E7EA45A1940D32066D64E39CBAFED8F2418D5A6DC30BF`。PE 时间戳 `0x51EA955E`、SizeOfImage `0x3BC000`、入口 RVA `0x28E1E0`。
- SDK 的 `external/Qube-Loader/modloader/sdk/cube/items.hpp` 定义物品类型。`modloader/src/game/offsets.h` 定义 `Creature+0x11DC` 的背包外层 vector、`0x11C` 字节物品格、`0x118` 字节物品本体；读取上限沿用 32 页、每页 256 格。
- `GameController+0x800954` 为玩家背包 Widget；`+0x800958` 为配方 Widget，`+0x80095C` 为商人库存 Widget。恢复文件 `external/CubeWorld-Reversal/cube/control/GameController.cpp` 构造段分别记录这些指针及 mode 0 / 2 / 3。玩家 Widget 的 `+0x160` 指向真实背包 vector，`+0x164` 为所属控制器，`+0x194` 为 mode。
- `0x4C2050` 的恢复名称是 `GameController::drawCurrencyPanel`，实际函数遍历 `this+0x160` 的背包格并绘制图标、数量、价格和钱币，写入 `this+0x184/+0x188` 的悬停页/格。本模块视其为 InventoryWidget 绘制函数；ECX 为 this，`0x4C597A` 为无参数清栈的 `ret`。
- 绘制还读取 `items+0x128` 的铜币总额和 `items+0x12C` 的白金币。因此视图包含原始 items 起的 `0x130` 字节前缀，只替换前 12 字节 vector 头，其余保持原值。
- `0x4C6610` 在 flag 非零时将悬停格复制到 `+0x18C/+0x190`，再计算选择框的位置；thiscall，`0x4C679E` 为 `ret 4`。调用前后换算索引，外部代码继续读取真实坐标。
- `0x62DC20` 给出 Widget 的屏幕原点（输出两个 float，`ret 4`）；`0x62F600` / `0x6291D0` 分别返回宽、高（x87 float，`ret`）。原绘制及 `0x4C6350` 滚动计算均读取 `+0x1A8/+0x1AC` 的格子宽高，并使用 `int((width-10)/(cellWidth+5))` 与 `int((height-40)/(cellHeight+5))`。标题和分区沿用这组公式，原点偏移仍为 x+10、y+40；没有固定列数或行数。原生滚动的当前页行偏移来自 `+0x198` vector，最大滚动范围在 `+0x1A4`。
- 每个标题占一行显示副本，末行按原版列数对齐；这些合成单元的映射为 -1，真实物品字节逐格保留。初次建立布局时隐藏未使用的原生空位；0.1.6 按用户最新要求记住已显示格的类别，售出或拿起后保留其空位，其他格不前移。同会话位置记录由绘制和滚动视图共用，按控制器/角色/背包原址隔离；不向真实背包插入空格。标题始终映射为 -1，持同页物品时可见空格指向已核实的真实空位。
- `0x4C6350` 不仅从绘制入口调用，也由原生交易后的更新路径调用。0.1.1 在此使用独立临时分区视图重算滚动，结束后还原指针；不能刷新用于点击校验的上一绘制快照，否则卖出后的过期悬停会被错误接受。辅助函数和滚动反汇编见 `research/evidence/inventory-sort-sections-native-disassembly.txt`。
- 原生详情节点：`GameController+0x8008E4` 为 `preview`，`+0x8008EC` 为 `equippedpreview`；构造段 `0x200239/0x20023B` 及原生更新段 `0x48ED12..0x48F177` 交叉核对。节点可见值按 `Node+0x3C -> state+0x68/0x94` 当前槽读取。`Node+0x34` 指向 Shape，`+0x40` 指向 Widget，`+0x48` 为当前 16 浮点变换矩阵；`+0x38` 是局部位置状态，不能当作 Widget。
- 0.1.3 尝试使用 `0x634A70`（恢复名称 `Node_transform_pair_to_screen`）测量，却遗漏从局部到屏幕的变换。用户的新截图确认 0.1.3 已加载仍遮挡；此前离线测试直接提供屏幕矩形，未覆盖这个坐标转换。旧反汇编保留在 `research/evidence/inventory-tooltip-native-bounds-disassembly.txt`，该方法不再用于 0.1.4。
- 0.1.4 的现场依据：用户授权保持卷轴悬停，2026-10-25 10:30:36 +08:00 只读采集 `inventory-tooltip-0.1.3-failure-live.json`，主详情可见。`SmoothMeshShape` vtable 原始地址 `0x71E92C`（现场重定位后 `0xE1E92C`）；其 vfunc 6 (`0x669080`) / 7 (`0x669060`) 分别返回 Shape `+0x878/+0x87C` 和 `+0x880/+0x884` 的局部边界，反汇编见 `inventory-tooltip-local-bounds-getters.txt`。这组边界已包含局部动画位置，不应再加 `Node+0x38`。
- 同一记录的局部边界约 `(45.1754,-119.8242)..(353.1759,188.1758)`，节点矩阵平移 `(793.8247,471.8243)`，换算后的屏幕外框约 `(839.0001,352.0001)..(1147.0006,660.0001)`。用局部框直接避让落在无关区域；0.1.4 以当前列主序矩阵变换四角并除齐次 w，取包围框、向外取整后再扩 3 像素。支持当前缩放和平移；矩阵、范围或已知 Shape 类型无法核实时隐藏本帧标题。只读取缓存，没有新增游戏函数调用。
- `inventory-tooltip-0.1.4-schema-live.json` 另核对对比节点使用相同 SmoothMeshShape 布局、不同当前矩阵；采集时对比隐藏，仅作布局依据。0.1.4 首次读到各可见节点的有效屏幕框时各写一条日志，供重开核对，不逐帧输出。合成 SDK 用局部框与独立节点矩阵重放现场，并要求省略平移的反例确实产生遮挡。
- 加载器在 D3D9 EndScene 后段绘制 ImGui，原生详情已存在于画面。更换 ImGui 自身的前景/背景列表无法改变它与原生窗口的先后关系。0.1.4 对标题的背景、分隔线、文字与空背包提示统一排除两个详情矩形（外扩 3 像素保留边缘），通过绘制裁切实现详情优先；不重画原生详情或改变格子坐标。
- 0.1.5 装备页回退现场：`inventory-equipment-0.1.4-replay-live.json` 在 2026-10-25 10:50:14 +08:00 记录 page 0 共 104 件，全为 count 1，类型均合法：胸甲 12、手套 10、鞋子 2、肩甲 8、武器 69、项链 2、戒指 1。玩家 vtable、Widget 归属、mode 0、items 原址、vector 长度与容量均通过原前提。完整物品字节另存 `inventory-equipment-0.1.4-cells.bin`，SHA256 `48106A183CB631FFC57AC9CAC9786FFBF3F04230848833C00894435BD87AF3F3`。
- 该 vector 为 `0x200AAAA8..0x200B1E08`，29536 字节。首个 VirtualQuery 区域 `0x200AA000..0x200B1000` 为 `PAGE_READWRITE`，后续 `0x200B1000..0x200B3000` 为 `PAGE_EXECUTE_READWRITE`；两段都可读，但整块跨界。加载器 `src/core/mem.cpp` 的 `readable/regionContains` 仅接受单个区域，`src/api/system.cpp` 的 `apiMemRead` 原样使用此检查。因此旧版的整页读和过期输入校验均可能失败。
- 0.1.5 仅在本 Mod 的 read 包装内处理此限制：保留整块成功的快速路径，失败且跨 4 KiB 页边界时，以页边界切片再次通过同一 SDK 读取。Windows VirtualQuery 区域以页为界；每段都保留权限、可读性及地址范围校验，任一失败仍回退，不直接 memcpy 游戏地址，不修改加载器或内存保护。合成 SDK 强制现场同偏移的单区域规则，并回放完整 104 件装备，验证七类、8 列、192 个含标题/对齐的显示单元、完整物品字节和尾段物品对应关系。
- 0.1.6 取放现场：`inventory-return-0.1.5-live.json` / `inventory-return-0.1.5-held-live.json` 分别捕获拿起前后。装备页 105 个原格，拿起后持有武器 count 1、type 3，原生槽 57 从有效武器变为真实空位，页内仍有 89 个空位。旧版重新紧凑分类后隐藏了原位置，只在全列表末尾增加“放回背包”一个槽；行末看似空格仍映射 -1，导致用户无法在可见位置放回。
- 原生左键路径 `0x47C54D..0x47C748` 先检查悬停页、格在真实 vector 内；持有物必须与原生 `getItemTypeCategory` (`0x47FA30`) 的页一致，然后由原生交换/堆叠处理。恢复源码 `GameController.cpp` 约 29547 行及 30774 行，与固定版本一致。该分类函数对 3..9、23、24 返回 0，对 11 返回 2，对 19/20 返回 3，其余返回 1；0.1.6 仅复用这张固定映射，不新增游戏调用或挂接点。
- 持有物完整 Cell 位于 `Creature+0x11E8`，Item 从 `+0x11EC` 开始，正是原 items 前缀的 +12。0.1.6 点击快照比较整个 0x11C 字节持有记录；同数量换物也能使旧映射失效。真实空位可拥有多个显示别名，反向选择优先使用最后实际悬停的显示位置，防止选择框跳去另一个别名。别名不创建、复制或写入实际物品格。
- `0x47B450` 返回玩家悬停坐标；`0x47B600`、`0x47DDD0` 的输入路径包含原生取放、装备或交易操作。本模块仅在输入前检查快照，不自行交易、不覆盖输入参数或返回值。
- 运行时核对绘制/选择入口、字段访问、返回栈清理及鼠标输入栈帧特征。反汇编见 `research/evidence/inventory-sort-native-disassembly.txt`。
- 药水钩子为 `0x44AD30`、`0x4C76E0`，照明为 `0x448170`；地图、探索没有修改本模块的五个挂接点。药水价格仅匹配商人临时库存，本模块只改变玩家 Widget 显示副本。标题使用原加载器的独立透传菜单，不拦截背包鼠标。此为离线兼容依据，真实同用仍待验收。

未修改公共加载器、启动器或原游戏文件。管理器的安装检测、独立开关、运行锁定及卸下备份沿用项目流程。
